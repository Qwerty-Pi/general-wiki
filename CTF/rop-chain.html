Return-Oriented Programming (ROP)

Why ROP? Since Stack NX (Non-EXecutable) is invented, we cannot simply write shellcode in the stack and run it directly. One way to bypass is to reuse known assembly code. Since we want to gain control on the control flow, we want some assembly code ends with ret (equivalent to pop rip). Since stuff ends with ret and we chain ret together, we call this return-oriented programming and ROP chain.

ASLR (Address-Space Layout Randomization): The virtual memory supports to be shuffled, but if only ASLR enabled the location of code segment would not be randomised. PIE (Position-Independent Execution) randomised the location of the code segment as well.

ROP Gadget

Gadgets are assembly codes like "pop rdi; ret;". Basically just write like shellcode. For example, *A = pop rdi; ret; then in the stack, we can put [___A___][__rdi__], then we can change the rdi value.

Dynamic Memory Allocation

mmap: allocate 0x1000 (page size) memory, involve kernal syscall. Can control rwx.

ptmalloc (POSIX-Thread): malloc (allocate chunk), free (free chunk), realloc (change size of chunk), calloc (allocate and zero-out memory), sbrk (allocate more bytes), brk (extend to certain address)

tcache: 0x40 bins (tcache_perthread_struct) for storing free-ed single linked-list of pointers (tcache_entry). Each list accounts for 0x10 bytes. Multiple layers of cache, very complicated.

metadata for malloc: [prev_free_size][cur_size | flags]@[usable (multiple of 0x10)]
